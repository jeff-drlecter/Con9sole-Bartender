## 最終規則（取代固定 2／3 人觸發方案）

- 僅有指定未來時間的預約局適用自動建立 Discord Scheduled Event；「現在玩」沿用招募卡。
- 發起人沿用「原有隊伍人數（包括自己）＋尚欠人數」；預設成局門檻為兩者相加，不新增必填步驟。
- 摘要明示「X 人成局，達標後自動建立活動」，發起前可修改最低人數、最高人數或關閉自動建立。
- 尚欠留空代表不限，不能推斷成局門檻，不自動建立 Event；可由管理選單另設。
- 原有隊伍人數是發起人申報，計入門檻；原有朋友毋須逐一再報名。提示「原有隊友不用重複報名」。
- 成局計數為申報原有隊伍＋有效、已確認報名；退出及待重新確認者不計。稍後到仍屬報名但須清楚標示。不得將任何報名／申報數當作實際到場。
- 達到門檻後自動建立一次活動，毋須另按成局確認。若發布時已達門檻，也只在明示摘要後的正式發起成功時處理。
- 活動與原約局卡互相連結；正式報名、名額、退出、稍後到繼續以原卡為準。
- Event「有興趣」不等於報名，不佔名額、不代開 Bot 提醒。
- 改期／取消同步已連結活動，保留原有改期重確認。人數回落不自動刪除重建；顯示最新狀態。
- 建立活動不等於開始活動或實際開局；實際場次、共同參與及 EXP 判定不改。
- Discord 原生活動通知與 Bot 通知不能承諾完全去重；活動啟動同步及其原生提醒時機須在實作交接中明確列出，不因本文件提早啟動活動。

## 新報名提醒發起人

- 新發起約局預設開啟「有人報名時提醒我」，摘要明示，可隨時關閉。不得批次替既有約局開啟。
- 成功新報名才觸發；重複按、滿額失敗、由已報名改稍後到不當新報名。新報名直接選稍後到則明示。
- 短時間多人報名合併；同一人退出重入需防重複洗版。
- 只在原組隊頻道發短訊息，僅 tag 發起人；無 DM、角色或 everyone mention。有權限成員仍可看到。
- 發送前核對發起人仍在群及原來源權限、本人開關、報名最新狀態。
- 達標與 Event 建立成功可合併一則提醒。只有已取得可核實 Event ID／連結才可寫「活動已建立」；失敗或未知不可冒充成功。
- 個人本局開局提醒仍預設關閉；它與發起人收到新報名提醒是不同開關，不得混用。

## 實作與驗收要求

- 建立 Event／發通知前持久記錄嘗試；同 plan 唯一綁定，並發達標只建立一次。
- 未知結果先核對，不盲目重播；明確失敗與未知分開。重啟不能補發舊報名提醒。
- 活動可見性不可洩露受限遊戲區。無法保持來源權限範圍時停用該局自動建立，不能為了 Event 放寬角色或頻道權限。
- Event entity type／臨時語音尚未建立時的目的地、結束時間及手動改動衝突，實作前依官方 API 與現行權限決定並記錄。
- 驗收涵蓋跨遊戲門檻、已滿額、申報隊友避免重算、稍後到、退出／改期重確認、關閉提醒、並發最後名額、Event 已存在／被刪／人工改動、403／timeout、重啟及未知不重播。
