# 收藏里程碑 v1

## 範圍

收藏頁顯示已收藏款數、目前酒譜完成度、下一個最接近目標、最近三款、徽章數。
「里程碑」顯示成就及 UTC 達成日期；用家可揀已解鎖徽章作展示稱號，亦可取消展示。
首頁 Quick Bar 不增加按鈕。稱號只顯示於 bot 收藏頁，並非 Discord 身分組。

## 舊資料承接與公平性

新增 drink_collection（每人每款一筆）、drink_collection_meta、drink_milestones、drink_collection_titles。
保留 drink_events 全部原始記錄。初次啟動時，舊 actor/target 收藏全部承接，包括過往請畀人嘅酒。
舊收藏喺查看或首次再收酒時靜默補計徽章，唔補發歷史通知。
遷移標記同 backfill 喺同一 transaction，重啟唔會將新送酒補算畀送酒者。
新事件只計收酒者收藏；同款重複收到唔增加圖鑑數目。
事件、收藏、成就同一 transaction；儲存失敗會整筆回復，唔顯示解鎖成功。
新成就合併喺原有酒卡，不另發公開訊息，不重複 tag。

日期由各酒款最早事件還原。酒譜完成度按當前 catalog 內嘅酒計；已下架舊酒仍保留收藏。
完成度成就用 catalog 名單雜湊識別版本，保存當時總數；加酒款唔會收回已解鎖徽章。

## 驗證與部署

本地 Python 3.14：113 個測試通過；正式 CI 用 Python 3.11（待提交後執行）。
已補測兩次 fresh Python process 重新讀取：舊收藏、里程碑日期及所選稱號一致。
測試包括舊 schema 遷移、舊送酒保留、新送酒歸屬、重複／並行事件、transaction rollback、跨 guild 隔離、稱號授權／保存、酒譜擴充保留舊徽章、Discord 行寬及提示發送失敗。
部署前：備份線上 SQLite，核對舊收藏總數、完整性同酒譜。
部署後：核對版本／啟動 logs，確認 migration marker、歷史 ownership 不減、SQLite integrity，驗證 Discord command sync。
實際 UI 驗收仍需用家開「收藏 → 里程碑」，試選稱號、重開收藏確認保存。
