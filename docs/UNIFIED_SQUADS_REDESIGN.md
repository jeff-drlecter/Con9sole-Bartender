## 目標與現況

跨遊戲成員用一個入口完成即時找人、預約、報名、開語音及完局。沿用「約一局」名稱；「搵人玩」的快速操作併入「現在玩」，不再並列兩個相同用途的入口。

目前有三份互不相連的狀態：Teams 即時招募、PlanBook 預約、SquadCards 語音場次。預約到時間就鎖定所有操作，卻沒有實際開局；Teams 把稍後到的人也當成「已齊人，可以開call」。三者不能靠改名解決。

## 一個入口

「約一局」開私人面板，只有三項：

- 現在玩：預填現在、當前遊戲、原有1人；先選尚欠1／2／3人／自訂，再填平台／模式。原有人數可改；不強迫再輸入時間。
- 約定時間：預填當前遊戲及原有1人；五格為遊戲、時間、平台／模式、原有人數、尚欠人數。不限名額需明確顯示，不能把空白解讀成欠0人。
- 我的約局：只顯示本人發起或報名且仍可操作的約局，連回原卡；歷史另按鈕查看，最近10項分頁。

從只讀指南進入時，先選本人及 Bot 都有權限的組隊目的地；未有遊戲身份組引導原生 Channels & Roles，不代派角色或繞過權限。遊戲分類可預填，但可選其他遊戲；發布地點仍須合適及有權限，不因輸入遊戲名授權存取。

## 原卡與操作

公開卡保持精簡：遊戲、時間、平台／模式、原有＋報名人數、尚欠名額、狀態、發起人；不直接展開名單。

預約／招募時：`我參加`、`稍後到`、`名單／選項`。報名者可切換準時／稍後，退出在私人選項內，不能重複佔位。私人回覆清楚說明「已計入原有隊伍的人不用再次報名」。

發起人的私人選項：`開局`、`修改約局`、`取消約局`。其他人不能替其開局或修改；管理員只可按既定權限取消，普通 Helper 沒有額外管理權。

開局確認頁顯示遊戲、平台／模式、報名人數、將使用的語音房及通知對象摘要。選用當前符合權限的同遊戲房，或建立本遊戲小隊房；禁止默認重用另一遊戲的自有房。沒有移動其他成員。房間建立成功不代表已在玩，先顯示「集合中」。

房間連結確認並有人進入後，原卡顯示`加入語音`、`報名／名單`；不另發同一場招募卡。單純自行入語音、沒有約局的場次，維持原有自動召人流程。

## 狀態與時間

| 狀態 | 觸發 | 可做甚麼 |
|---|---|---|
| 預約中／招募中 | 成功發卡 | 報名、稍後到、退出；發起人修改或取消 |
| 待開局 | 到預定時間 | 保留上述操作；發起人可開局或改期 |
| 集合中 | 已確認語音房 | 顯示房間入口；尚不宣稱實際開玩 |
| 進行中 | 已綁定場次且符合既有真人語音啟動條件 | 加入語音、看名單；原有報名不等於到場 |
| 已結束 | 綁定場次依現有完局規則結束 | 唯讀參與紀錄、通知設定、再約一局 |
| 已取消 | 發起人或有權限的管理員取消 | 原卡保留、名單唯讀、再約一局 |
| 未開局 | 預定時間後2小時仍沒有綁定場次 | 保留報名紀錄；重新約局以新紀錄及新報名開始 |

滿額只表示名額已被預留，不表示大家已就緒、已到場或自動開局。稍後到佔預留名額，但獨立顯示人數；沒有實際身份的原有朋友只記數量。實際參與者只由該場真人語音紀錄產生，不把報名及朋友人數灌入足跡、EXP或出席。

集合房為空被現有 TempVC 清理時，解除失效連結並返回待開局／招募中；已開過的場次不能再次自動當成全新局通知。開始及完局時間採實際場次時間，不採預約時間。

## 變更與報名意願

- 更改遊戲、平台／模式或時間：保留原名單及舊資料版本，原報名標為「待重新確認」，不當成仍同意新安排；當事人由原卡一鍵確認或退出。未確認者不佔新安排的確定名額，私人名單仍可查舊意願。
- 只改人數：保留已確認報名；不能縮至少於原有隊伍＋已確認報名。
- 稍後到、準時到是預計到達意願，不冒充實際在場。
- 不提供自動踢未到者、強制移動、候補遞補或轉讓主辦，避免第一版增加不必要邊界。

## 通知設計（尚未啟用）

目前預約不會自動通知報名者，亦沒有開局提醒。新設計必須把這點改成清楚可見的產品行為；以下是待實作規格，不能宣稱現已運作。

1. 新版報名確認明示「開局時會在此頻道提醒你一次；不會私訊」，成員可在選項停用本局提醒。舊報名沒有這項同意，不追溯替其開啟；保留原報名，僅在其重新操作時提供選擇。
2. 真正開局才有一次精簡提醒。對象為有本局提醒意願的已確認報名者，與同遊戲有效的一次／長期訂閱者的聯集；同一人同一場只提醒一次，已在房內的人不重複通知。
3. 原有朋友沒有帳號對應及本人意願，不猜身份、不代報名、不代訂閱。提醒前重新核對成員、頻道及語音權限；退出、取消或撤回提醒後，尚未發送的項目也須排除。
4. 新建預約、滿額、時間到、單純建空房及 Bot 重啟，不觸發遊戲訂閱、不消耗「下次」名額。一次訂閱只在下一個符合條件的實際遊戲場次依既有收據機制處理。
5. 提醒訊息放現有組隊頻道，可被該頻道有權限的其他人看見；只有指定成員被提及，不宣稱「只有被通知者看得到」。Discord 是否推送也受成員通知設定影響，不保證每人收到手機推播。
6. 改期／換遊戲與取消預設只更新原卡；若新增通知，要另有清楚的同意與授權，不能借開局通知順便啟用。沒有 DM、全體或角色群組 ping，沒有新公告或新通知頻道。

加入這類新通知的部署範圍須先由 Jeff 確認；目前不改現有通知行為。

## 完局與再約

沿用既有足跡門檻、真人參與者快照、去重收據及空房緩衝。不把預約當新足跡來源。符合門檻才發一張足跡；原卡改精簡結束摘要及足跡連結。短暫／單人場次不新增團體足跡，原卡可顯示已結束。

足跡保留「本局參與者」、「下次通知名單」、「下次通知我／每次通知我」及「再約一局」入口。再約只預填遊戲和模式，另選時間及人數，不帶入上次報名、不自動代參加、不複製一次通知意願。

## 舊紀錄遷移與回復

1. 維護時先在持久磁碟備份 PlanBook JSON、team_cards SQLite（含 WAL 正確快照）、SquadCards JSON、訂閱／發送收據及參與者快照。先 dry-run 輸出數量及狀態映射，不在公開 repo 放真實名單、訊息ID或備份。
2. 驗證 JSON及各原紀錄；失敗則停止該來源遷移並保留原檔，不採用「讀不到等於空資料」。保留未知欄位，新增 schema 與遷移版本；atomic write、映射表及每步收據讓重啟可續跑。
3. 既有預約保留 id、message、channel、owner、start、party、members、capacity、歷史及連結，不刪卡或重新發卡。舊 status=started 只代表時間已到，不得映射為進行中或實際出席。
4. 切換時仍在預定開始後2小時內的舊到期卡，回到待開局，保留全部報名；更早的舊到期卡標為「歷史預約・開局情況未核實」，唯讀保留，不擅自宣稱未成局、已取消或曾玩過。未來卡正常沿用。
5. Teams 活動卡以穩定 legacy key 映射，保留原 message ID、發起人、現在／稍後名單及期限。舊 required 是欠隊友數，新 party=1、capacity=1+required；不能把 required 當總人數。已有取消／過期卡不復活。
6. 所有舊 teams:…、plan:…、固定入口及足跡按鈕由相容處理器轉入同一服務；不因新卡介面而留下無回應舊按鈕。既有指令作別名保留，主選單只顯示一個「約一局」。
7. 不從遊戲名、時間或同一發起人推測綁定既有語音場次。只有發起人明確選擇且重新檢查權限後綁定；一房／一場最多一個活動約局，避免吞掉其他卡或雙發足跡。
8. 遷移及卡片更新一律 allowed_mentions.none，禁止追補提醒、補發足跡、消耗訂閱或補算EXP。無法對應的資料保留供管理員核對，不清空處理。
9. 發卡 posting 結果不明不自動重發，列管理員健康檢查。不存在或無權限的舊訊息不重建公開卡；紀錄保留並顯示不可用。新的 schema／事件寫入啟用後，舊版不能直接覆寫新資料；回復須先停止寫入，再還原相容備份或使用已驗證的逆向轉換。

## Bot 其他接點

- 同一遊戲識別資料供分類預填、目的地、語音、訂閱及足跡使用；支援所有遊戲及公海，保留遊戲版本識別，不能誤把不同年度遊戲訂閱合併。
- `/menu`、快捷列、指南固定入口、舊組隊別名、每日任務及說明統一用「約一局」。現有「小隊 call」仍供純開語音使用，不要求每次語音都先填卡。
- 成功且持久保存的新約局只計一次既有組隊每日任務；表單開啟、瀏覽、重試、改期、遷移、重啟及開局不重複給EXP。實際語音EXP沿用原本出席來源。
- Helper 概覽只在其原有可查看範圍顯示待開局／尚欠人等摘要，細節重新核權；不新增提醒、不開放核心設定、不公開私人名單。
- 固定公共卡及按鈕中性繁中；私人面板、驗證錯誤及成功回覆採個人儲存的HK／TW語言，未選中性；重啟不重置偏好。
- Carl 後備、Ranking、身份組、邀請來源及 Adventure 不因本次整合改動。預約服務不額外取得管理員權限。
