# 主題酒單 v1 — 功能及驗收說明

基線：GitHub main `f5762d161314006fcaf3d78cc3ff2675878386c4`。
開發分支：`codex/theme-collections-v1`。用戶已於 2026-10-19 授權再次 review，檢查通過後部署。實際部署結果以 Actions 及上線驗收報告為準。

## 今版玩家會見到甚麼

收藏總覽新增一張推薦／追蹤卡，以及「🗺️ 主題酒單」按鈕。
打開後揀三張主題之一；預設睇進度，詳細酒單同進階目標放入次一層。

| 酒單 | 固定範圍 | 入門 → 進階 → 精通 | 精通稱號 |
|---|---|---|---|
| 🍸 吧枱初體驗 | 常駐 5 類，2,092 款 | 任意 3 類 → 5 類；每類一款就計 | 吧枱探索家 |
| 🌴 熱帶假期 | 常駐熱帶酒 334 款 | 3 → 10 → 25 款不同酒 | 熱帶漫遊者 |
| 🥃 經典巡禮 | bot 既有經典清單 78 款 | 1 → 3 → 10 款不同酒 | 經典收藏家 |

三張自動同時計數，無需報名；同款可以符合多張酒單，重複獲得不加款數。
追蹤只改首頁卡片，取消追蹤會恢復自動推薦。已完成入門的玩家會獲推薦下一張；三張入門完成後再推薦未精通的酒單。
階段獎章會升級同一張酒單的顯示；不要求收齊 334 或 78 款才算完成。

酒單按鈕：進度、睇未收藏／未集類別、完整酒單、階段目標、追蹤／取消追蹤。
清單每頁 12 款，顯示中英真名、稀有度及收藏狀態；初體驗「未集類別」會過濾已探索的類別。
可直接返回收藏總覽或打開現有稱號選單。查看其他人的收藏時不能替對方追蹤、換稱號或讀取其私人通知。

## 主要畫面文案

初體驗：
> 任意收藏 **3 類酒，每類 1 款**，就完成第一張酒單。
> **2 / 3 類**，再探索 1 類就達標。
> ✅ 調酒系　✅ 熱帶系　⬜ 氣泡系　⬜ 薑味／騾子系　⬜ 醇厚系

熱帶假期：
> 收藏酒單內任意 **3 款不同熱帶酒**，就完成第一站。
> 莫吉托、戴吉利都計，唔使指定抽中邊款。

經典巡禮：
> 遇到酒單內 **任何 1 款經典**，就可以起步。
> 78 款都計，唔使等某一款。呢張適合慢慢儲。

共用頁尾：
> 舊收藏照計｜同款唔重複計｜追蹤唔會增加抽中機率｜進度唔會重置

舊收藏補計：
> 舊收藏已補計 **N 個階段**，唔使重新儲。
> 精通稱號可到「里程碑」選用；目前稱號會保留。

## 抽取機率與可持續性

今版保留 Common / Rare / SSR = **85% / 12% / 3%**。
最近 4 次抽中的酒權重 1，其餘權重 4；同稀有度內按此抽取。兩個權重已命名為常數並加回歸測試。
每季 2,096 款可抽；固定主題清單不包含季節限定，不因轉季卡關。
追蹤、獲獎或選稱號均不改抽取權重；沒有付費加速、必中、日更重置或保底。

保留機率的原因：入門目標不要求某一款 Rare 或 SSR。現有機率配合分階段門檻已涵蓋短、中、長期目標，毋須為推進度永久增加稀有酒產量。

先前以相同機率及秋季池做 10,000 次模擬（seed 20261019）：

| 目標 | 中位抽數 | 約九成玩家達標抽數 |
|---|---:|---:|
| 初體驗 3／5 類 | 4／21 | 8／49 |
| 熱帶 3／10／25 款 | 16／58／151 | 31／82／190 |
| 經典 1／3／10 款 | 19／73／277 | 62／144／405 |

這些是零收藏、同一人自行抽酒的模擬，不是必中承諾或 production 實測。舊收藏及朋友請飲會減少需要自行抽取的次數。長期仍應以實際參與及完成分佈檢視門檻，下一版調整須保留既有獎章與 v1 清單。

## 舊收藏、稱號與通知

- 直接讀既有 `drink_collection` 所有權，保留里程碑 v1 補計過的歷史送酒收藏；新送酒只計收酒者。
- 舊資料按玩家首次讀取收藏或下一次收酒時補計，沒有全服公告，也不批量掃描／改寫所有舊事件。
- 舊達標標示「舊收藏補計」；補計時戳是處理時間，不冒充歷史達成日期。
- 新事件、收藏、里程碑及主題解鎖在同一 SQLite transaction；失敗一起 rollback。唯一鍵防止同時事件重複頒獎。
- 新主題解鎖合併為私人提示；新送酒的收酒人下次開收藏時才收到摘要，不向送酒人洩露私人提示，不發陌生 DM。
- 通知成功後只確認本次送出的 award IDs；失敗保留待讀，新增進展不被較舊的確認清除。訊息已送出但確認寫入失敗時，下次可能重見一次摘要；不會重發獎章。
- 精通稱號沿用現有選擇／取消展示流程；獲獎不自動覆蓋選擇。

## 資料與檔案

- `assets/theme_collections_v1.json`：凍結常駐 2,094 款名稱、分類、稀有度及經典資格；記錄來源 SHA。跟程式發佈，與 runtime `/data` 分開。
- `features/theme_collections.py`：門檻、進度、獎章、追蹤、私人通知待讀紀錄；只新增 `drink_theme_awards`、`drink_theme_preferences` 兩張表。
- `features/theme_views.py`：清單、分頁、進度、追蹤及稱號入口。
- `features/drink_storage.py`：把主題解鎖接入原有收酒 transaction。
- `features/collection_milestones.py`：共用稱號選單讀取主題精通資格，沒有把主題獎章塞入舊里程碑表。
- `features/drink_embeds.py`、`features/drink_views.py`、`cogs/drink.py`：收藏入口、推薦卡、私人通知、原有稱號流程。
- `data/drink_data.py`、`features/drink_catalog.py`：將既有近期降權值命名；機率數值不變。

回退舊程式時，新表可以保留；舊收藏及舊里程碑仍可讀。若已選用主題稱號，舊程式不會顯示它；重新升級後仍能讀取原選擇，除非期間用戶另選稱號。不要為回退刪除資料表或回復過期整庫備份。

## 本地驗證

全套 **134 個 unittest 通過**（原有 113 + 新增 21）。
涵蓋名單一致性、實際舊 schema migration、舊所有權補計、多主題同時計數、同類／同酒不重複計、送酒歸屬、跨伺服器隔離、同時送酒去重、transaction rollback、新 process 重啟後獎章／稱號／追蹤保存、通知失敗／重試、無權限修改、分頁及 Discord 元件／embed 限制、主題私人提示不出現在公開結果。

本地環境：Python 3.14.8、discord.py 2.7.1。另已按 Python 3.11 grammar 檢查所有 Python 原始碼。新增模組及新測試的 Ruff 檢查通過；全專案致命錯誤規則通過。
未啟動真實 Discord bot、未連線驗收 Discord、未執行 Python 3.11 runtime／Docker 或 GitHub Actions，也未測 production database migration。

## Review 後的實際驗收清單（尚未執行）

1. 對照既有帳戶收藏款數及現有稱號；首次開收藏只收到一則舊進度摘要。
2. 打開三張主題，確認舊酒款已計入及缺少酒名可見。
3. 追蹤熱帶酒單，重開收藏首頁仍顯示該張；取消後恢復推薦。
4. 自己抽到新酒／重複酒；只有新達門檻才出私人摘要。
5. 請朋友飲：只有收酒人增加收藏／主題進度，送酒人不收到對方主題通知。
6. 自然達標後選用主題稱號、切換、取消；重開及重啟後保留。
7. 查看其他人的收藏：不能替對方改追蹤／稱號，也不會消除其待讀提示。
8. 新手及已精通帳戶檢查按鈕、分頁、超時重開與 mobile 顯示。

部署前需通過 Python 3.11 CI、完成最新資料備份；上線後逐筆核對舊收藏及稱號，真人 UI 驗收另行記錄。
