## 量度定義與判讀

1. 有意義回覆：真人帳戶提供遊戲、時段、玩法、具體需要／回饋；排除營運本人、已確認測試/副帳、Bot、純emoji、重複廣告及只有讚。六篇跨帖按帳戶去重，未知帳戶真實性不能認證為不同真人。私下保留必要去重證據，公開只用獲准聚合。作者回覆不計門檻。
2. 加入事件：沿用 referral_joins 的 (guild,user,joined) 事件鍵；同碼及跨碼重入保留。各碼COUNT(DISTINCT user)不能相加當全來源不同成員；left_at IS NULL僅代表該次未觀察離開，非目前留存。fresh是首次記錄，不保證首次加入或不同真人。
3. 來源：現有match_batch只在2秒批次單碼delta可解釋整批時歸因；離線、權限/邀請遺失、多碼變動/數量不符等保留unknown，重連不回填離線入群。不能以lifetime uses差值替代事件。兩個Threads碼先分列，再由04/06在私人範圍按帳戶去重作cohort；保留跨碼重入及其他來源/unknown。
4. 歸因層級：同窗Threads標籤碼加入是「碼關聯加入事件」，不證明看過某篇。共用profile碼無逐帖ID，因此P01/P04間不能分配加入功勞；自然流量、舊置頂及外部轉貼仍是混雜。不可把所有Threads加入稱為本campaign造成。
5. 首次觀測合資格到場：04的邀請加入 cohort → 到場聚合介面尚未交付，結果目前為unknown／pending。cohort為主要入群窗內Threads碼關聯、排除Bot及已確認測試帳戶且標示重入的帳戶；只量度加入後 `[joined, joined + 7*86400)` 首次觀測到合資格非Bot帳戶到場。joined為加入事件時間；到場恰在joined時計入，恰在joined + 7*86400時排除。as_of為資料觀測截止時間；只有 `as_of >= joined + 7*86400` 才成熟，較早為pending，等號成熟但右界到場仍不計。這是rolling加入窗，不等於04的香港日曆回訪cohort。既有「首次觀察」不是入群；缺cohort與attendance/visits連接、完整coverage或先前歷史時保持unknown，不補0或成功。未有完整已確認測試帳戶registry，須列排除範圍未驗證；非Bot帳戶不證明獨立真人，首次觀測不證明首次遊玩。文字聊天與語音／session證據分開，訊息量、獎勵或XP不替代到場。成熟分母、分子、pending、unknown並列，先前已有到場紀錄的重入帳戶另列，不充新帳戶首次觀測到場。
